# 图文视频工坊 · 使用手册（给 agent 看的）

这份文档是给**新会话里的你**看的。读完你应该知道：这个插件能干什么、什么时候用哪个参数、交付前查什么、哪些坑已经踩过。

引擎目录跟着插件走（插件会自动找到，也可以用 `TUWEN_ENGINE` 指定）。第一次用、或者用户说「出不了片」时，先跑一次自检：

```
node src/cli.js doctor          # 逐项检查 node/ffmpeg/ffprobe/Chromium/配音引擎/API Key
```

**关于 API Key：不要向用户索取 Key，也不要把 Key 贴进对话。** 缺 Key 就让他自己跑 `tuwen setup`——那会开一个本机页面，他在浏览器里填，直接写进 `~/.dsh/tuwen/.env`。
没有图像 Key 也能出片，只是画面是占位图（`result.degraded` 为 true），不算成品。

---

## 你的角色

你不是在"调用一个渲染接口"，你在当导演。工具负责执行，判断在你这里——选风格、写台词、决定哪一镜要重出、判断图有没有跑题。这些机器替不了。

---

## 三条铁律

1. **先出分镜表，人看过再出图。** `video_studio_build` 不带 `confirmed` 只返回分镜表，一分钱不花。分镜表上的时长是**真跑了一遍配音量出来的**，不是估的。

   这条不是靠你自觉：插件会按 spec 内容记账。**没见过这张分镜表的 spec，就算你传了 `confirmed` 也只会再返回一次表**（返回里带 `gate: "not-seen"`），不会出图也不会花钱。spec 改一个字就是另一个分镜，得重新给人看一次。看到这个返回，你要做的是把表拿给人看，不是重试。
2. **配音引擎按整条决定，绝不逐句混用。** 一条片子里出现两个嗓子，比音质差一点糟糕得多。工具已经强制：volc 中途失败会整条退回 edge。
3. **交付前必看 `imagesSheet`。** 质检 7/7 只说明技术指标合格（黑帧、冻帧、响度、码率…），不能说明画面讲对了话。

---

## 工具报错怎么看

工具失败时返回里一定有 `error`（发生了什么）和 `hint`（下一步做什么）。**照着 hint 做，不要原样重试一次。**

| 返回里的 `kind` | 意思 | 你该做什么 |
|---|---|---|
| `bad-args` | 你传的参数不对：缺了、类型错、格式不符 | 消息里写了期望什么，改参数重试 |
| `internal` | 插件自己出 bug 了 | 把 error 和 hint 里的日志路径一起转告用户，别自己猜 |

引擎跑挂了（`ok:false` 但没有 `kind`）通常是环境或输入的问题：先跑 `doctor` 看环境，再看 `error` 里的 stderr 尾巴。

## 选型速查

| 内容类型 | `style.preset` | 配音 |
|---|---|---|
| 科普 / 知识 / 新闻 | `flat` 或 `cinematic` | edge + `news` |
| 故事 / 短剧 / 悬疑 | `cinematic` | edge + `warm` 或 `passion` |
| 爽文 / 热血 | `manga` | volc + `reference` |
| 搞笑 / 日常 | `comic` 或 `storybook` | edge + `funny` 或 `cute` |
| 绘本 / 儿童 | `storybook` | edge + `cute` |
| 黑板讲解 / 科普动画 | `chalk` | edge + `news` |

画幅只支持 **9:16 和 16:9**（已实测）。1:1 和 3:4 代码里有路径但没验证过，别用。

## spec 最小骨架

```json
{
  "id": "my-video",
  "title": "标题",
  "aspect": "9:16",
  "style": { "preset": "cinematic" },
  "voice": { "preset": "warm" },
  "scenes": [
    {
      "id": "s1",
      "narration": "第一句台词，就是字幕。",
      "visual": {
        "subject": "看得见的东西：主体、动作、材质、光、背景",
        "shot": "中景，人物居中偏右"
      },
      "transitionOut": { "type": "crossfade", "duration": 0.45 }
    }
  ]
}
```

有角色时加 `characters`（`look` 和 `outfit` 写死在提示词里，同时当参考图用），镜头里用 `cast` 引用。

## 分镜怎么写

- **3~8 镜**，30 秒左右。少于 3 镜，语气曲线和换人停顿不生效。
- **每句 12~20 字**，口语，第一句是钩子。超过 42 字字幕要折两行，观感会散。
- **`visual.subject` 写看得见的东西。** 「更有电影感」对模型是零信息；「桌上一张揉皱的试卷，边缘被台灯照得发亮」才有用。
- **`visual.shot` 用数字约束构图。** 「人物高度不超过画面四分之一」模型会听；「很有张力」不会。
- **转场一条片子 2~3 种就够**，全片一种会闷，全片五种会晕。
- **一条片子只用一套 `style.preset`**，混着用画面就糊了。

## 配音

优先级：**镜头 `scenes[].voice` > 角色 `characters[].voice` > 项目 `voice`**。

- `speaker` 管**谁在说**，`cast` 管**画面里有谁**。两个人同框但只有一个人开口，就是 `cast: ["a","b"]` + `speaker: "a"`。
- 换人说话会自动留 0.45 秒停顿，旁白↔对白 0.55 秒。不用手调。

**两个引擎：**

| | edge | volc |
|---|---|---|
| 特点 | 免费、确定性、逐句可控、14 个中文音色 | 会演，能听懂「带着疲惫说道」 |
| 适合 | 科普、新闻、知识、长解说 | 故事、对白、爽文、情感 |
| 代价 | 不会演 | 慢 5 倍；时长长 30~50%；生成不确定 |

用 volc 时记得两件事：`rate` 给 **+25~35%** 才追得平 edge 的节奏；**必须给 `voice.reference`**（一段你认可的参考音频），否则音色锚点取当次第一句，换条片子嗓子就变。

## 交付前检查

**第一件事是看图，不是看数字。** `build` 返回里的 `shots[]` 每一镜都带着 `narration` 和 `image` 路径，直接打开它，问三个问题：

1. 这张图讲的是**这句话**吗？
2. 有没有多出来的文字、水印、对话气泡？
3. 主体有没有被切掉，画面有没有空白带或黑边？

你看得懂图，这件事不需要任何工具，只需要真的去看。机型能查的（黑帧、冻帧、响度、码率）都是**技术指标**，它们全绿也不代表画面对。

**改的规则：**

- 单镜不对 → `video_studio_scene` 只重出那一镜。
- **同一镜最多重出 2 次**。两次还不对，问题在台词或描述，改字，别继续摇。
- 整体不对（风格跑偏、节奏不对）→ 回去改 spec 重来，别一镜一镜抠。
- **不要追求每一镜都完美**。一条片子里有一两张平庸的图是正常的，把时间花在开场的前两镜上，那里决定观众留不留。

剩下的才是看数字：

- `result.qc.checks` 七项全绿。
- `result.degraded` 必须是 `false`——为 `true` 说明有画面用了占位图，技术指标照样合格，但不是成品。
- 时长和分镜表差不超过 5%；响度在 -14 ±1 LUFS。

**质检能挡住什么、挡不住什么**（说清楚，免得你误以为 7/7 就等于没事）：

| 会挡住 | 挡不住 |
|---|---|
| 图片解不开（出图时就拦，写 .part 校验后才改名） | 图能解开但画错了内容 |
| 整段黑帧、音轨缺失、响度跑偏、时长对不上 | 画面「几乎不动」——颗粒层每帧都在抖，冻帧检测实际只能抓到逐像素完全相同的帧 |
| 字幕和软字幕对不上（SRT 由同一份时间轴导出） | 字幕挡住了人脸、主体被切掉 |

所以第二条永远是人的事：打开 `imagesSheet`，一张一张看。

改完代码先跑 `npm test`（离线、约 25 秒、21 项断言：冒烟 16 + 闸门 5），再谈别的。

## 长片与断点续渲

**5~10 分钟能做吗？** 代码里没有硬上限，但有两件事要知道：

1. **渲染约为片长的 3 倍。** 实测 124 秒的片子渲染 393 秒。10 分钟 ≈ 30 分钟渲染。
2. **只有 2 分钟实测过**（50 镜 / 123.87 秒 / 3716 帧 / 质检全过）。5 分钟以上是外推，没跑过。

**中途崩了会不会全废？** 不会，分四层缓存：

| 东西 | 崩了之后 |
|---|---|
| 出图 | `缓存按内容哈希，不重出、不重复花钱 |
| 配音 | 按句子内容缓存，不重合 |
| 逐帧渲染 | **按镜记账**，渲完的段直接跳过；崩在第 40 镜，下次从第 40 镜接着来 |
| 混音/合成 | 很便宜，每次都重做 |

实测：10 镜的片子渲完一次 38.6 秒，第二次全部跳过只要 9.3 秒。

**什么情况会让某几镜重渲：** 那一镜的时间轴、字幕或图片内容变了。改一句台词只影响那一镜的配音和它之后的整体时间轴——后者会让后面所有镜的时间变化，所以台词改动的影响面比想象的大。

**做长片的正确姿势**：分章。每章一个项目（2~3 分钟），各自成片，最后再拼。这样一章崩了不牵连别的章。

| 项 | 安全区 | 超了会怎样 |
|---|---|---|
| 角色数 | ≤ 3 | 每个角色一张定妆照，同框参考图超过 3 张模型容易串脸 |
| 总时长 | ≤ 5 分钟 | 渲染约为片长的 3 倍（实测：124 秒的片子渲染 393 秒），中途失败要整条重来 |
| 单镜台词 | ≤ 20 字 | 字幕折两行，观感散 |

超过 2 分钟已经实测过：50 镜、123.87 秒、3716 帧、质检全过。所以长片是能做的，只是**失败成本高**——渲染期间任何一步崩了，重来一遍就是几分钟。做长片就分章，每章一个项目，最后再拼。

## volc 的音色锚点

第一次用 volc 时，旁白第一句会被自动存成 `assets/volc-anchor.mp3`。**之后所有片子都用它**，所以跨条片子嗓子是同一个。

- 想换一把嗓子：删掉这个文件，或者给 `voice.reference` 指定别的音频。
- 角色各有各的锚点（各自第一句），不会共用，所以多角色不会被压成一个声音。

## 工作台

`node src/cli.js studio` 起来的是**审片台**，不是编辑器：分镜缩略图、整片预览、**每一镜单独的配音试听**，加上一条写入路径（改某一镜的画面描述后重出图/重渲）。

它解决的问题是：整片连着听，分不清是哪一镜的配音别扭；在这里点哪一镜就听哪一句。

真正的编辑仍然是对话——你说要改什么，agent 改 spec 再重跑。别指望在工作台里改台词或改结构。

## 角色一致性

每个角色会先生成一张**四视图设定图**（正面 / 左侧 / 右侧 / 背面，横图 2560×1440），存在 `img/_char_<id>.jpg`。这是这个角色的资产，每一镜都把它当参考图传进去。

提示词里会自动写明：「每张参考图是同一人物的四视图设定，只取本镜需要的角度」。所以：

- **转身、侧面、背面不用特殊写法**，正常写在 `visual.subject` 里（「背对镜头看向窗外」）就行。
- **同框**：`cast: ["lin","zhou"]` 会按顺序传两张参考图，提示词里会标「参考图1是林夏，参考图2是周野，两个人不能串脸」。
- **人数上限**：1~2 人最稳，3 人可以试，**超过 3 张参考图模型容易串脸**。
- **前后遮挡**：用 `visual.shot` 写清谁在前景谁在背景，别让模型自己分配。
- **换装 / 受伤 / 时间跳跃**：不要指望一张设定图管到底，另起一个角色 id（`lin` → `lin-broken`），让引擎单独出资产。

角色参数只认三个字段：`look`（年龄、发型、脸型、疤/痣/眼镜，越具体越好）、`outfit`（服装，写颜色和材质）、`voice`。

## 封面与发布

封面不是抽帧，是单独排的：拿一镜的画面当底，压暗，把钩子放上去。

```json
{
  "title": "爽文试拍 · 满分",
  "coverTitle": "全班都以为我是废物",
  "coverShot": "s1",
  "kicker": "爽文 · 第 1 集",
  "platform": "douyin"
}
```

- `coverTitle` 写**钩子**，不是片名。不填就用 `title`。
- `coverShot` 指定底图用哪一镜；不填就自动挑：有角色的第一镜，否则中间那镜。
- `kicker` 是标题上方那行小字。

`platform` 决定字幕的安全区（底部 UI 会盖住多少）：

| platform | 字幕离底边 |
|---|---|
| `douyin` | 17.2% |
| `xiaohongshu` | 15% |
| `wechat` | 18% |
| `bilibili` | 9.5% |
| `youtube` | 10% |

写错平台名会退回 douyin 的值，不会报错——发布前自己确认一眼。

## 成片版本

每重渲一次，旧成片会被挪进 `out/history/<时间戳>.mp4`，保留最近 5 个；`out/versions.json` 记下每一版的时长、体积、是否通过、用的哪个配音引擎。

**退回上一版：**

```
node src/cli.js restore projects/<id>/project.json --to=1
```

`--to=1` 是上一版，`--to=2` 是上上一版。换之前当前这版也会被归档，所以**回退和反悔是同一条命令**——试错成本只是一次文件复制。回退后 `qc.json` 和 `result.json` 会跟着更新，不会留下上一版的质检结论。

不满意的时候先回退，再想怎么改，别急着在坏版本上继续叠。

## 交付开关（spec 里的 deliver）

| 开关 | 默认 | 关掉会怎样 |
|---|---|---|
| `burnSubtitles` | true | 不挂字幕层，成片无字幕；SRT 照常导出，方便后期自己叠字 |
| `cover` | true | 不出 `cover.jpg` |
| `srt` | true | 不导 `out/<id>.srt` |
| `crf` | 20 | 数字越小画质越高、体积越大（16 接近无损，26 明显糊） |

`crf` 变了会触发整条重渲——画质是编码期决定的，不重渲等于没改。

## 常见坑

1. **别用 `--fast` 交付。** 那是字数估算，和真实配音差 20% 左右。只适合快速看结构。
2. **volc 不指定 `reference`，跨片音色会变。** 实测同一句提示词两次调用，中位基频差 26 Hz。
3. **改单镜用 `video_studio_scene`**，25 秒；但它会重新出图，不想换图就加 `noImage`。
4. **角色定妆照第一次要额外一张图**，缓存后不再花。
5. **别在提示词里写「底部留白 / 底部预留字幕空间」。** 模型会照字面画出一条空白带，很难看。字幕安全区靠主体位置解决，不靠留白——这条已经写进引擎的构图约束里了。
6. **漫画风爱自己画对话气泡，还带乱码中文。** 负向词里已经有「对话气泡」，别删。
7. **字幕描边靠 `paint-order: stroke fill`。** 改字幕样式时删了它，描边会跑进字里面，字就细得看不清。
8. **字幕位置按高度比例算**，不是写死的 330px。改画幅时别写死。
9. **内容审核是概率性的。** 单张被拒会自动换种子重试一次；还失败就补占位图，并把整条标记为降级。
10. **缓存按内容哈希。** 改了台词才会重新合成，改画面描述才会重新出图——所以改一个字，成本可能不是"一个字"。
11. **`leadIn` 别大过上一镜。** 提前量比上一镜的全部内容还长时，这一镜会「倒着开始」，帧区间被压成 0 宽，成片里直接少一镜。现在引擎会自动截短并在分镜表里报 warning，但那是补救，不是支持。
12. **改了画幅/调色/字幕样式/平台/CRF，会整条重渲**（这些参数现在进渲染指纹了）。改之前先想清楚，别在长片上随手试。

## 更像人的做法

- 写完分镜先问自己：**第一句能不能让人停下来**。
- 台词念出来听一遍再定稿，写的时候顺、念出来未必顺。
- 别让每条片子都长一样：换风格、换音色、换节奏，是三个独立的旋钮。
